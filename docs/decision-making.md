# 技術選定と意思決定 — Microsoft Teamsを採用した理由

> **対象：** 大学陸上競技部の幹部向け情報共有基盤  
> **従来の連絡手段：** LINE  
> **比較・検討対象：** Microsoft Teams / Slack  
> **位置づけ：** 採用時の判断観点を整理したポートフォリオ資料。料金・契約条件・大学の利用規程などは利用時点で別途確認が必要です。

## 1. 判断が必要だった背景

陸上競技部は複数キャンパスにまたがり、短距離・長距離など担当領域も分かれています。また、幹部は年度ごとに交代するため、その場限りの連絡手段ではなく、**後任者が過去の議論・資料・決定事項を追える仕組み**が必要でした。

### 従来のLINE中心の運営と課題

従来、幹部間の連絡や情報共有には主にLINEを使用していました。LINEは日常的な連絡を素早く行いやすい一方、継続的な組織運営の観点では、次の課題があると考えました。

- **重要情報の埋没：** 日常のやり取りと決定事項が同じトークに流れ、後から確認しづらい。
- **業務ごとの分類：** 会計・行事・会議などの話題を体系的に整理しにくい。
- **引継ぎの難しさ：** 幹部交代時に、議論の経緯や関連資料をまとめて渡しにくい。
- **個人への依存：** 情報が個人のトーク履歴や手元の資料に分散しやすい。

これらはLINEの機能そのものを否定するものではなく、**日常連絡に適した使い方と、組織の知識を蓄積する仕組みでは求められる役割が異なる**という課題です。

そこで、LINEを全面的に廃止するのではなく、幹部の業務に関する議論・決定事項・資料の整理に適した環境を別途整備する方針で、文書の保管、役割分担、管理権限の引継ぎを含めて検討しました。

## 2. ツール選定の評価軸

| 評価軸 | 確認したいこと | この組織で重要な理由 |
| --- | --- | --- |
| 話題の整理 | 業務別に会話を分類できるか | 会計・行事・会議などの情報が混ざるのを防ぐ |
| 文書管理 | 資料を保管し、後から参照できるか | 幹部交代時に知識を引き継ぐ |
| アカウント・権限 | メンバー変更や権限管理ができるか | 卒業・役職交代への対応が必要 |
| 既存環境との親和性 | 大学で利用できるサービスと連携しやすいか | 導入・管理の負担を抑えたい |
| 運用のしやすさ | 新しい幹部が使い方を理解できるか | 特定の担当者に依存しないため |

## 3. LINE・Teams・Slackの位置づけと比較

LINEを従来の連絡手段として位置づけたうえで、幹部業務を整理するための新たな環境としてTeamsとSlackを比較しました。両サービスともチャンネルを使った情報整理に対応しています。機能の優劣を一律に決めるのではなく、**今回の利用環境との適合性**を重視しました。

| 利用目的 | LINE（従来） | Teams / Slack（検討対象） |
| --- | --- | --- |
| 日常的な素早い連絡 | 既存の連絡手段として活用 | 利用可能だが、移行を目的化しない |
| 業務ごとの議論・決定事項 | トークの流れに混在しやすい | チャンネル単位で整理できる |
| 文書・引継ぎ資料の蓄積 | 個別のやり取りに分散しやすい | 保管先と運用ルールを設計しやすい |

※上記は本プロジェクトで想定した運用上の比較であり、各サービスの機能を網羅的に評価したものではありません。

### TeamsとSlackの比較

| 観点 | Microsoft Teams | Slack | 判断のポイント |
| --- | --- | --- | --- |
| チャンネルによる分類 | 対応 | 対応 | どちらも業務別の整理に利用可能 |
| ファイルの扱い | SharePoint等との連携を前提に設計できる | ファイル共有や外部ストレージ連携が可能 | 文書の継続保管をどう設計するか |
| 大学の利用環境 | 大学のMicrosoft 365環境との整合性を検討 | 利用契約やアカウント管理を別途検討 | 実際の契約・利用条件の確認が必要 |
| 幹部交代 | チーム所有者やメンバーの管理方法を設計する | ワークスペースの管理者・メンバーの引継ぎを設計する | 管理権限が個人に固定されないこと |
| 導入後の運用 | Teamsと文書管理の役割を整理する必要がある | Slackと文書保管先の役割を整理する必要がある | 毎年の引継ぎ負担を抑えられるか |

※この表は検討観点の整理です。機能の提供範囲はプラン・管理設定等によって変わるため、製品仕様を網羅した比較表ではありません。

## 4. 選定結果

**従来のLINEによる連絡を前提に、幹部業務の情報共有・記録を整理するためMicrosoft Teamsを採用しました。**

今回の設計では、Teamsを幹部業務に関する連絡・議論の場とし、文書の保存・引継ぎについてはSharePointとの連携を視野に入れています。チャットと文書の管理を切り離して考えるのではなく、**「誰が、どこに、何を残し、次年度にどう渡すか」**を一体で設計できることを重視しました。

採用理由をまとめると、次の3点です。

1. **情報の分類：** 業務別のチャンネルを設け、必要な議論や連絡を探しやすくする。
2. **資料の継承：** 日常連絡だけでなく、引継ぎ資料の保管先と管理方法も検討できる。
3. **継続運用：** 幹部交代を前提として、管理権限や運用ルールを設計する。

## 5. 選定後の実装

Teamsでは、次の11チャンネルを設けています。

| 番号 | チャンネル | 主な目的 |
| --- | --- | --- |
| 01 | 全体連絡・決定事項 | 幹部全体への共有と決定事項の記録 |
| 02 | 運営方針・業務改善 | 運営方針や改善案の検討 |
| 03 | 部則 | 部則の検討・整理 |
| 04 | 会計 | 会計に関する連絡・資料整理 |
| 05 | 合宿・行事 | 行事の準備・運営 |
| 06 | 引き継ぎ・マニュアル | 後任者向けの知識・手順の整理 |
| 07 | 会議 | 会議関連の連絡・記録 |
| 08 | 新歓・広報 | 新歓活動や広報 |
| 09 | スケジュール | 日程の共有 |
| 10 | OB関連 | OBに関する連絡・調整 |
| 11 | 備品 | 備品管理 |

詳しい構成は [情報共有基盤の設計資料](system-design.md) に記載しています。

## 6. 現時点の限界と今後の検証

幹部向けにチャンネルの作成と構成整理は進めていますが、LINEからの全面移行を完了したという意味ではありません。また、**導入による時間削減や情報共有の改善効果は、現時点では定量的に検証できていません。** また、文書管理・権限引継ぎの方針には継続検討中の項目があります。

今後は、資料の検索しやすさ、情報の見落とし、役員交代時の負担などを確認し、構成やルールを必要に応じて見直します。

## 7. この検討で示したい能力

- **要件整理：** 利用者や組織構造から、必要な機能・運用条件を整理する力
- **比較検討：** 単純な機能比較ではなく、利用環境との適合性で選ぶ視点
- **運用設計：** 導入時だけでなく、担当者交代後の継続性を考える力
- **実装への接続：** 判断した方針を、具体的なチャンネル構成に落とし込む力
